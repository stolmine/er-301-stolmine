# v0.7.0-stolmine.9.1.0

Release date: 2026-04-17

## Summary
Expanded FileRecorder sourcing plus LocalChooser UX polish across AdminMode.
Resolves the long-standing Tomograph visualization regression, which was traced
to a package-side libm issue. ABI-compatible with v9.0.0 — no package rebuild
required.

## What's new
- **FileRecorder: Locals tab enabled.** The source picker's Locals tab now
  works from the FileRecorder, letting tracks be sourced from unit outputs,
  branch outputs, or patch monitoring outputs inside any chain — the same
  sources `LocalChooser` already exposed elsewhere in the app. Previously the
  FileRecorder was limited to Jacks + Globals because it constructed
  `SourceChooser` without a chain.
- **LocalChooser: chain-select LEDs.** Chain buttons light to indicate which
  root chain the picker is currently browsing. LED state persists across
  AdminMode user/scope switches and is re-asserted when the picker is
  re-shown.
- **LocalChooser: empty-overview warning.** Chains with no patchable sources
  now display a `[chain]: No units.` placeholder instead of a blank view.

## Enhancements
- **LocalChooser: live refresh on re-show.** The picker re-resolves the
  selected channel's root chain on `onShow` and reseeds its `ChainOverview`
  when the selection has changed, so backing out of the picker and changing
  channels no longer leaves a stale overview.
- **AdminMode + LocalChooser: persistent LED across user/scope.** The
  chain-select LED follows the active user and scope changes in AdminMode
  rather than snapping back after every re-entry.

## Fixes
- **Tomograph visualization regression resolved.** Traced to package `.so`
  libm `sinf`/`cosf` miscompute on am335x when called from dynamically
  loaded packages. The firmware side is clean; the fix lives in the
  Tomograph package (precomputed LUT). Investigation archived in
  `docs/HABITAT_TOMOGRAPH_VIZ_REGRESSION.md`.

## Known issues
- **LocalChooser may display stale state after stereo link/unlink in user
  mode.** If the Locals picker is reopened on the same channel after the
  user links or unlinks a stereo pair, it can paint against a destroyed
  chain reference. The main channel view and `OUTX: No units` readouts are
  unaffected — they rebuild correctly via `Channels.show()`. Workaround:
  fully exit the picker before changing stereo link state. Fix planned for
  the next release; design is recorded in
  `docs/planning/chain_invalidation_on_link_unlink.md`.

## Internal / docs
- Habitat Tomograph viz regression investigation note added and marked
  resolved.
- Planning doc for the chain-reference invalidation bug
  (`docs/planning/chain_invalidation_on_link_unlink.md`).
- Multitrack recorder Locals feasibility note archived in
  `docs/planning/multitrack_recorder_locals_feasibility.md`.

## Upgrade notes
- Install the firmware zip normally via the front SD card's
  `ER-301/firmware/` directory.
- Delete any prior `core-*`, `teletype-*`, `txo-*` packages on the SD card
  before installing to avoid the version-match skip on first boot.
- ABI-compatible with v9.0.0 — third-party packages built for v9.0.0 load
  unchanged.
