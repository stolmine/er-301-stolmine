# ER-301 UI operation: the gesture catalog

*Layer 0 of the `ui-model` cluster (planning/ui-model-plan.md §1 + §5). The
human-and-agent quick-reference for driving the 301 UI deterministically: the
gesture vocabulary, the logical-gesture to emu-control-protocol mapping, the
M1-M6 slot convention, and the canonical gestures with their verified
control-protocol sequences.*

The 301 UI is a **dispatch-by-named-method state machine over a window/context
stack**. A physical button becomes a fixed `notify(event, ...)` event
(Application.lua `defaultDispatcher`); the visible `Context` routes it to the
focused widget's chain of responsibility. So the affordance set at any moment is
the union of gesture events some object in the focus chain (or the context)
handles. The exhaustive machine form of that surface is
`testing-assets/emu/ui-model.manifest` (extracted by `tools/extract_ui_model.py`);
this doc is the readable subset.

## How to drive it

Gestures are issued to the headless emu over the line protocol
(planning/headless-emu-plan.md §2): `down B` / `up B` / `press B` for buttons
(`B` = `MAIN1-6`, `SUB1-3`, `SELECT1-4`, `DIAL1-3`, `ENTER`, `UP`, `SHIFT`),
`turn N` for the encoder, `mode {up,center,down}` and `storage {up,center,down}`
for the two toggles, and `frames N` to settle. Confirm where you landed with the
linchpin accessor:

```
lua require('Application').getVisibleContext():top():getClassName()
```

(with `...:getInstanceName()` as the per-channel tie-breaker). This is exactly the
`recognize` predicate style used in `testing-assets/emu/ui-map.toml`.

### Gesture vocabulary (notify events)

The complete `notify(event, ...)` alphabet (Application.lua `defaultDispatcher`). Every Window/Control/Mode handler name is drawn from exactly this set:

- `cancelPressed`, `cancelReleased`, `cancelRepeated`, `commitPressed`
- `commitReleased`, `commitRepeated`, `dialPressed`, `dialReleased`

## Button to notify wiring (the non-obvious bits)

The three dial-column buttons and the SHIFT modifier fold several logical
gestures onto few keys (Application.lua `defaultDispatcher`; hal/events.h
`EVENT_PRESS_*`):

- `DIAL1` -> `dialPressed/Released/Repeated` (the "dial mode" button).
- `DIAL2` -> `cancelPressed/Released` (this is CANCEL).
- `DIAL3` -> `homePressed/Released`; **SHIFT + DIAL3** -> `zeroPressed/Released`.
- `ENTER` -> `enterPressed/Released`; **SHIFT + ENTER** -> `commitPressed/Released`.
- Every gesture also carries a trailing `shifted` boolean (true while SHIFT is
  held), so a handler like `Dense:mainReleased(i, shifted)` sees the modifier.

## The two toggles

Orthogonal hardware switches, driven with absolute positions (verified live):

- **STORAGE** selects the top-level mode: `storage up` -> user (per-channel edit,
  `Chain.Root`), `storage center` -> admin (`Menu`, instance `Admin`),
  `storage down` -> eject (`Card.StatusViewer`).
- **MODE** selects the per-channel view: `mode center` -> edit (`Chain.Root`),
  `mode down` -> scope (`Chain.ScopeView`), `mode up` -> hold (`SceneView.Performance`
  with scene mode on).

## Canonical gestures (verified live against the headless emu)

Every sequence below was driven against `emu.elf --headless --seed 301` on the
hermetic fixture (`testing-assets/emu/fixtures`, `pickerStyle=dense`,
`animation=disabled`) and confirmed via the linchpin accessor / state query shown.
They are regression-guarded by `tests/emu/51-ui-model-canonical.test`.

### Link chord: link chains 1+2

Hold SELECT1, then tap SELECT2 while held (UserMode.lua `selectPressed`: the first
press selects + latches the channel, the adjacent press toggles the link). Both
chains empty -> no confirmation dialog, links immediately. Context is unchanged
(state-only gesture).

```
lua tostring(require('Channels').serialize().links.link12)   -> @ok false
down SELECT1 / frames 6
down SELECT2 / frames 6
up SELECT2 / up SELECT1 / frames 10
lua tostring(require('Channels').serialize().links.link12)   -> @ok true
lua ...getVisibleContext():top():getClassName()              -> @ok Chain.Root
```

### Open / close the unit picker

On the empty boot chain the insert section spans MAIN3-MAIN5; pressing MAIN3
selects that spot, whose `mainReleased -> spotReleased` fires
`EmptyControl:activateChooser` (plain ENTER does NOT reach it: the cursor sits on
the header). CANCEL (DIAL2) closes it.

```
lua ...:top():getClassName()   -> @ok Chain.Root          (boot)
press MAIN3 / frames 14
lua ...:top():getClassName()   -> @ok Unit.Chooser.Dense  (picker open)
press DIAL2 / frames 12
lua ...:top():getClassName()   -> @ok Chain.Root          (closed)
```

### Focus + expand a unit

Picking a unit from the dense chooser inserts it into the focused chain and lands
it focused in its **expanded** view. `Dense:mainReleased(1)` picks the
left-column entry; its own spot (MAIN1) then toggles the view.

```
lua require('Channels').getChain(1):length()                    -> @ok 0
press MAIN3 / frames 14                                          (open picker)
press MAIN1 / frames 16                                          (pick left column)
lua ...:top():getClassName()                                    -> @ok Chain.Root
lua require('Channels').getChain(1):length()                    -> @ok 1
lua (select(2, require('Channels').getChain(1):getSelection())) -> @ok expanded
press MAIN1 / frames 12                                          (toggle the view)
lua (select(2, require('Channels').getChain(1):getSelection())) -> @ok default
```

### Enter / exit admin (STORAGE center)

storage center / frames 20
lua ...:top():getClassName()      -> @ok Menu
lua ...:getInstanceName()         -> @ok Admin

lua ...:top():getClassName()      -> @ok Chain.Root

### Enter / exit scope (MODE down)

```
mode down / frames 12
lua ...:top():getClassName()      -> @ok Chain.ScopeView
mode center / frames 12
lua ...:top():getClassName()      -> @ok Chain.Root
```

### Enter / exit the sequencer (SHIFT + ENTER, from scope)

The grid sequencer is a sub-view of scope mode: enter scope first (`mode down`),
then SHIFT+ENTER (`commitReleased`) toggles the takeover on and off.

```
mode down / frames 12
lua ...:top():getClassName()      -> @ok Chain.ScopeView
down SHIFT / press ENTER / up SHIFT / frames 12
lua ...:top():getClassName()      -> @ok Sequencer.GridView
down SHIFT / press ENTER / up SHIFT / frames 12
lua ...:top():getClassName()      -> @ok Chain.ScopeView
```

## Provenance and keeping this in sync

- **Vocabulary + slot tables** (the GENERATED block) are emitted from
  `testing-assets/emu/ui-model.manifest` by `tools/extract_ui_model.py --catalog`.
  `scripts/dev ui-model` regenerates the manifest, diffs it against the committed
  baseline, AND checks this doc's block is in sync (`--check-doc`); drift fails the
  gate. `STOL_UPDATE_UI_MODEL=1 scripts/dev ui-model` regenerates both.
- **Canonical transcripts** are hand-authored from live emu runs and pinned by
  `tests/emu/51-ui-model-canonical.test` (run via `scripts/dev test`); if a gesture's
  effect changes, that test fails.
- **Cross-check with the runtime layer.** The manifest's per-class declared
  affordances are the static superset; the live `uiState().gestures` reflected at a
  node (Layer 1, `ui-model-introspect`) must be a subset of them. Same §1
  vocabulary, so the two are directly comparable.
